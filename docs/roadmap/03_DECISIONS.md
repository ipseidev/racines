# Registre des décisions techniques

Format : décision, pourquoi, alternatives écartées, réversibilité. Numérotation `T-nn`. Les décisions produit (D-7, D-8, D-9) restent dans le dossier produit, doc 05 R-12.

## Décisions fondatrices (2 septembre 2026)

**T-01 — Stack : Laravel + Inertia (React, TypeScript) + Postgres.** Pourquoi : maîtrise de l'équipe, écosystème Spatie/Filament mature, Inertia évite une API séparée tout en gardant React pour les interfaces riches (recorder, lecteur). Écartées : Next.js (deuxième langage, hébergement UE moins simple), Livewire pour le front utilisateur (moins adapté au recorder). Réversibilité : faible, c'est le socle.

**T-02 — Hébergement : serveur DigitalOcean existant piloté par Forge, région européenne obligatoire.** Pourquoi : déjà en place, Forge gère PHP, Redis, Horizon, scheduler, SSL. Condition : le droplet doit être en `ams3` ou `fra1` ; si ce n'est pas le cas, créer un droplet UE et y rattacher le site avant le bloc 16. Écartées : Laravel Cloud (AWS, moins de contrôle sur la région et le coût), Scaleway (pas d'outillage existant). Réversibilité : moyenne, Forge est portable vers un autre VPS.

**T-03 — Base de données : Postgres managé DigitalOcean dans la même région, sauvegardes quotidiennes et PITR activés.** Pourquoi : le dossier exige une restauration testée et un RPO borné ; le managé donne le PITR sans opération. Écartée : Postgres installé par Forge sur le droplet (moins cher, mais restauration artisanale). Réversibilité : élevée.

**T-04 — Stockage objet : Cloudflare R2, buckets créés avec juridiction UE, endpoint `*.eu.r2.cloudflarestorage.com`.** Pourquoi : choix de l'équipe, S3-compatible, pas de frais de sortie. Point de vigilance : Cloudflare est une société américaine ; la restriction de juridiction, le DPA et une mention dans l'AIPD sont obligatoires (bloc 16). Alternative sans changement de code : Scaleway Object Storage (même driver S3). Trois buckets : `media`, `media-replica`, `backups`, chacun avec un jeton d'accès distinct. Réversibilité : élevée.

**T-05 — Admin interne : Filament, réservé au back-office. Interfaces utilisateur : React custom.** Pourquoi : Filament accélère le support ; jugé trop brut pour des seniors et des acheteurs. Réversibilité : élevée.

**T-06 — Email : Resend (transport Laravel officiel `resend/resend-laravel`). SMS : Twilio via le SDK officiel `twilio/sdk` derrière l'interface `SmsSender` (pas de package de canal tiers, pour garder un seul point d'abstraction).** Pourquoi : choix de l'équipe. Twilio supporte l'expéditeur alphanumérique en France pour les messages sortants sans réponse ; un numéro de repli reste configuré. Réversibilité : élevée, interfaces `SmsSender` et mailer Laravel.

**T-07 — Rendu Fluide : Claude via le SDK PHP officiel `anthropic-ai/sdk`, modèle `claude-opus-5`, `outputConfig.effort = medium`, sortie structurée par schéma JSON, prompt système mis en cache.** Pourquoi : qualité de réécriture en français, SDK officiel, sortie structurée qui évite tout parsing fragile. Le modèle et l'effort sont des variables d'environnement. Le repli serveur en cas de refus (`fallbacks`) est activé par défaut sur l'appel bêta ; si le SDK installé ne l'expose pas, on gère `stopReason = refusal` en conservant le verbatim seul. Écartée : Mistral (souveraineté, mais qualité non évaluée par l'équipe). Réversibilité : élevée, interface `StoryRenderer`.

**T-08 — Transcription : Gladia comme premier adaptateur, Deepgram comme second, décision par banc d'essai WER sur corpus de voix âgées au bloc 06.** Pourquoi : Gladia est française, hébergée en UE, bonne en français, avec vocabulaire personnalisé et horodatage des mots ; Deepgram sert de référence de qualité. Voxtral (Mistral) non retenu faute de connaissance de l'équipe ; peut devenir un troisième adaptateur. Réversibilité : élevée, interface `TranscriptionProvider`.

**T-09 — Capture audio : `MediaRecorder` natif, tranches de 5 s stockées dans IndexedDB, upload multipart résumable vers R2 par URLs présignées (parts de 5 Mio).** Pourquoi : aucune dépendance lourde, reprise après rechargement, l'objet n'est confirmé qu'après `CompleteMultipartUpload` et `HeadObject`. Écartées : tus (serveur supplémentaire), upload via le serveur PHP (double transfert). Réversibilité : moyenne.

**T-10 — Traitement audio : ffmpeg via `pbmedia/laravel-ffmpeg` ; l'original n'est jamais réencodé, un MP3 128 kb/s est dérivé pour la lecture et l'export.** Réversibilité : élevée.

**T-11 — PDF du livre : `spatie/browsershot` (Chromium) avec Paged.js pour la mise en page, une passe Ghostscript vers PDF/X-1a quand l'imprimeur sera connu.** Pourquoi : HTML/CSS testable, un seul moteur de rendu, pas de service supplémentaire. Écartées : Prince (payant), LaTeX/Typst (courbe d'apprentissage), Gotenberg (Docker absent sur Forge). Réversibilité : moyenne.

**T-12 — QR : `endroid/qr-code`, URL `https://{LINKS_DOMAIN}/q/{token}`.** Réversibilité : élevée.

**T-13 — Machine d'états : `spatie/laravel-model-states` avec classes de transition explicites et gardes.** Pourquoi : transitions déclaratives, testables une à une, impossibilité structurelle d'une validation implicite. Réversibilité : moyenne.

**T-14 — Réglages : `spatie/laravel-settings` (`BrandSettings`, `PilotSettings`) édités dans Filament ; `config/brand.php` porte les défauts.** Pourquoi : le nom, le domaine et les couleurs doivent changer sans déploiement. Réversibilité : élevée.

**T-15 — Feature flags : Laravel Pennant, portée projet.** Pourquoi : les deux variantes de validation et les tests de prix du dossier sont des flags par cohorte. Réversibilité : élevée.

**T-16 — Paiement : Stripe Checkout (page hébergée) + Laravel Cashier pour clients, webhooks et remboursements.** Pourquoi : conformité PCI minimale, prise en charge SCA, remboursements outillés. Réversibilité : moyenne.

**T-17 — Authentification : Fortify pour les Initiateur·rice·s (email + mot de passe, vérification d'email, 2FA optionnelle) ; Filament avec MFA obligatoire pour le back-office ; jetons porteurs et OTP pour narrateurs et proches.** Réversibilité : moyenne.

**T-18 — Journal d'audit : table `audit_logs` maison, append-only par trigger Postgres, chaîne de hachage `previous_hash → hash`.** Pourquoi : « journalisation inviolable de toutes les actions support (lecture comprise) » du doc 04 §12 ; un package générique ne bloque pas les `UPDATE`. Réversibilité : faible par nature.

**T-19 — Analytics : PostHog cloud UE, capture serveur par défaut, front uniquement hors pages à jeton, URL nettoyées.** Écartées : Plausible (pas de funnels par utilisateur), Matomo auto-hébergé (opération). Réversibilité : élevée.

**T-20 — Erreurs : Flare. Disponibilité et page de statut : Oh Dear.** Pourquoi : hébergés en UE, intégration Laravel native. Réversibilité : élevée.

**T-21 — i18n : fichiers `lang/fr/*.php` partagés au front par prop Inertia, hook `useT()` maison, test d'existence des clés.** Pourquoi : zéro dépendance, français seul au MVP, mais aucune chaîne en dur pour permettre EN/ES en Phase 2. Réversibilité : élevée.

**T-22 — Tests : Pest (parallèle), Larastan niveau 8, Vitest + React Testing Library, Playwright (Chromium en CI, matrice d'appareils réels manuelle), `@axe-core/playwright`.** Réversibilité : faible, c'est le contrat de qualité.

**T-23 — Identifiants : UUID ordonnés (`HasUuids`) pour tout modèle exposé ; jetons de 32 octets aléatoires encodés base64url, stockés hachés SHA-256.** Réversibilité : faible.

**T-24 — Environnement local : Laravel Sail avec `pgsql`, `redis`, `mailpit`, `minio` (émule R2 en local), `clamav` à partir du bloc 12 ; image Sail publiée et étendue avec ffmpeg et Chromium.** Réversibilité : élevée.

**T-25 — Organisation du dépôt : la racine est le projet Laravel ; les documents produit vont dans `docs/dossier/`, les captures dans `docs/reference/` (ignorées par git).** Pourquoi : Forge déploie la racine ; les documents restent versionnés avec le code. Réversibilité : élevée.

**T-26 — Démo « essayez en 60 secondes » : enregistrement local seulement, lecture immédiate, aucun envoi au serveur.** Pourquoi : zéro donnée personnelle collectée sans achat, zéro coût de stockage, et le test d'ergonomie porte sur le micro et le bouton, pas sur l'upload. Réversibilité : élevée.

**T-27 — Limites d'enregistrement : alerte douce à 10 min, arrêt à 20 min, taille maximale 200 Mo, formats acceptés `audio/webm`, `audio/mp4`, `audio/ogg`, `audio/mpeg`, `audio/wav`.** Pourquoi : le dossier ne fixe pas de durée par histoire ; le fair use mensuel (60 min) borne le total. Paramètres dans `config/product.php`. Réversibilité : élevée.

**T-28 — Heure d'envoi par défaut : cadeaux à 09:00 Europe/Paris ; prompts au créneau choisi par le narrateur (matin 09:00, après-midi 14:00, soir 18:00) le jour choisi ; tick du moteur toutes les heures à la minute 07 ; dispatch des prompts toutes les 5 minutes.** Réversibilité : élevée.

## Décisions prises en cours de route

Format : `T-nn — date — bloc — décision — pourquoi — à revalider par l'humain : oui/non`.

**T-95 — 2026-09-03 — bloc 09 — La règle détecte et agit, le tick enregistre.** L'interface de l'annexe C faisait écrire `engine_events` par chaque règle (`fire(): EngineEvent`) et calculer la clé d'idempotence à chacune (`occurrenceKey()`). Les deux sont remontés d'un cran : `fire()` rend le contenu de `action_taken`, le tick insère la ligne **avant** l'action et dans la même transaction, et `Occurrence` calcule la clé. Motif : la clé unique en base est ce qui empêche deux ticks concurrents d'envoyer deux fois le même message, et cette garantie ne doit pas dépendre de onze implémentations qui pourraient se tromper sur l'ordre. Corollaire : la formule de clé n'existe qu'à un endroit, donc elle ne peut pas diverger. À revalider : non.

**T-96 — 2026-09-03 — bloc 09 — Le test du vocabulaire interdit lit les valeurs traduites, pas les fichiers.** Il parcourait le contenu brut de `lang/fr` : un commentaire expliquant « ne jamais écrire *dernier rappel* » le faisait échouer, ce qui pousse à écrire des commentaires évasifs sur le sujet précis où il faut être explicite. Il charge désormais les tableaux et parcourt les chaînes. Deux effets de bord utiles : il ne peut plus être trompé par une expression coupée en deux, et il ne s'applique plus qu'aux fichiers **du produit** — « ce champ est obligatoire » dans `validation.php` est du français correct pour un formulaire, pas une faute de ton envers un narrateur. À revalider : non.

**T-97 — 2026-09-03 — bloc 09 — Un test comparait `now()->subHour()` au début de la journée.** `RecordConsentTest` créait une version 2.0 « il y a une heure » pour qu'elle prime sur la 1.0 semée « au début du jour ». Entre minuit et une heure, l'heure en arrière tombe la veille, et la 1.0 gagnait. Trouvé en travaillant après minuit, ce qui est la seule façon de trouver ce genre de chose. À revalider : non.

**T-98 — 2026-09-03 — bloc 09 — L'option téléphone ouvre un ticket, la ligne `phone_options` attend le bloc 10.** `OfferPhoneOption` vérifie le drapeau, refuse franchement quand il est fermé — « nous vous rappelons » qu'on ne tiendrait pas serait pire que rien — et ouvre le ticket support que le bloc demande. La ligne `phone_options(entry=rescue)` viendra avec sa table au bloc 10 ; le drapeau étant fermé par défaut, aucune famille n'est concernée entre-temps. À revalider : non, le bloc 10 la crée.

**T-99 — 2026-09-03 — bloc 09 — Un événement supprimé ne consomme pas l'idempotence, et ne compte pas comme un message.** Trouvé en écrivant la cinquième règle. Quand deux règles veulent parler au même narrateur le même jour, la seconde est consignée comme supprimée — mais elle écrivait la `dedupe_key` de l'occurrence, si bien que le rappel seulement **différé** n'aurait jamais pu partir ; et elle était comptée dans « deux rappels maximum », si bien que le narrateur en aurait reçu un au lieu de deux. Les événements supprimés portent désormais une clé datée, et tous les compteurs de limite lisent les messages **partis**. À revalider : non.

**T-100 — 2026-09-03 — bloc 09 — `TokenService::peek()` : vérifier un lien sans le consommer.** Une action en un tap doit **montrer** avant d'agir — un lien reçu par SMS qui agirait à l'ouverture serait déclenché par le simple aperçu d'un client de messagerie. Or la page de confirmation d'un jeton à usage unique le grillait avant que son propre bouton puisse jouer. `resolve()` devient `peek()` + consommation, et le middleware accepte `resolve.token:action,peek`. À revalider : non.

**T-101 — 2026-09-03 — bloc 09 — Le numéro de relance est le discriminant d'occurrence, jamais une date ni un compteur d'état.** Première version : la clé de « trois histoires sans réaction » portait le nombre d'histoires partagées, celle de l'alerte J+21 le mois courant. Dans les deux cas la clé ne changeait pas d'une fois sur l'autre, et la seconde sollicitation n'était jamais envoyée — la règle se croyait déjà passée. Les quatre règles concernées comptent maintenant leurs envois et utilisent ce numéro. À revalider : non.

**T-102 — 2026-09-03 — bloc 09 — « Aucune histoire depuis dix jours » inclut le dixième jour.** La détection excluait les projets ayant une histoire `recorded_at >= now-10j`, donc au dixième jour pile la règle se taisait et ne parlait qu'au onzième. Comparaison stricte : à dix jours pile, le silence dure bien dix jours. Vaut aussi pour la règle des vingt-et-un jours. À revalider : non.

**T-103 — 2026-09-03 — bloc 09 — `whereColumn` entre une clé polymorphe et un uuid casse en Postgres.** `access_tokens.subject_id` est un `varchar` (il porte des sujets de plusieurs tables), `stories.id` un `uuid` : Postgres refuse de les comparer sans transtypage, et l'erreur n'apparaît qu'à l'exécution de la requête. Le transtypage est explicite (`stories.id::text`) et commenté là où il se trouve, parce que la prochaine règle qui joindra les jetons rencontrera le même mur. À revalider : non.

**T-94 — 2026-09-02 — bloc 08 — La suite de tests impose son propre environnement.** Les `<env>` de `phpunit.xml` ne s'appliquent que si la variable est **absente** de l'environnement : l'intégration continue exportait `QUEUE_CONNECTION=database` pour son serveur de bout en bout, et les tests PHP héritaient de ce pilote. Trois tests de purge, verts en local avec une file synchrone, échouaient en CI pour une raison invisible dans le code. `force="true"` est posé sur ce que la suite **possède** — file, cache, session, courriel, et les quatre fournisseurs simulés — et laissé sur ce que chaque environnement possède, les hôtes de connexion. Corollaire : les tests qui dépendaient d'une file synchrone jouent désormais le job explicitement, parce qu'un test ne doit pas dépendre d'un pilote. À revalider : non.

**T-86 — 2026-09-02 — bloc 08 — Un lien porte désormais son détenteur.** `access_tokens.issued_by` disait qui a émis le lien ; il manquait qui le détient. Un lien d'histoire (`listen_story`) a une histoire pour sujet : sans porteur il est anonyme, ce qui contredit la règle §9 du bloc — « un lien par personne, jamais un lien famille commun » — et rend la visibilité restreinte inapplicable, puisqu'on ne sait plus qui écoute. `issued_to_type` / `issued_to_id` sont ajoutés, nullables, et un lien d'histoire sans porteur est **refusé** à la résolution plutôt que traité comme anonyme. Le support (bloc 11) en aura besoin aussi. À revalider : non.

**T-87 — 2026-09-02 — bloc 08 — Le middleware de jeton accepte une liste de types.** `resolve.token:listen_project|listen_story` : l'espace famille a deux portes qui mènent à la même page. Le périmètre reste **déclaré sur la route**, jamais deviné dans un contrôleur — c'est ce qui le rend vérifiable d'un coup d'œil sur le fichier de routes, et un test parcourt la table pour s'en assurer. À revalider : non.

**T-88 — 2026-09-02 — bloc 08 — L'URL d'écoute est signée sur l'adresse vue par le navigateur.** `MediaStorage::temporaryUrl()` déléguait à `Storage::temporaryUrl()`, qui signe sur l'endpoint du **serveur** : en local le navigateur ne le résout pas, et l'audio ne joue rien (`ERR_NAME_NOT_RESOLVED`). Même correction que pour les envois présignés du bloc 04 (T-56) : on signe avec le client `public`. Le défaut serait passé inaperçu jusqu'en production le jour où l'endpoint public diffère du privé — c'est-à-dire exactement le jour où R2 est derrière un domaine à soi. À revalider : non.

**T-89 — 2026-09-02 — bloc 08 — Après une navigation Inertia, `back()` ne revient pas où l'on croit.** Un proche arrive sur une histoire par navigation client ; l'en-tête `Referer` du navigateur pointe encore la liste. `back()` le renvoyait donc à la liste après sa réaction, en lui faisant perdre sa place **et** la confirmation de son geste. Les contrôleurs de l'espace famille redirigent explicitement vers la route de l'histoire. Règle générale : `back()` n'est fiable que sur une page atteinte par un chargement complet. À revalider : non.

**T-90 — 2026-09-02 — bloc 08 — Une histoire hors de portée rend un 404 amical, sans dire pourquoi.** `abort(404)` affichait la page d'erreur du framework : technique, en anglais, et avec des styles en ligne sans nonce — trois manquements d'un coup à la convention §16. `StoryUnavailable` rend une page Inertia en langage simple avec un retour vers la liste. Elle ne dit **pas** le motif : ni « pas encore validée », ni « masquée », ni « réservée au livre ». Un proche qui apprendrait qu'une histoire existe mais lui est refusée en saurait déjà trop, et le narrateur n'a pas à justifier ses retraits auprès de sa famille. À revalider : non.

**T-91 — 2026-09-02 — bloc 08 — Le lecteur audio ne compte pas un saut de curseur comme de l'écoute.** Les secondes rapportées sont mesurées sur l'avance réelle de la lecture, et une avance supérieure à deux secondes entre deux `timeupdate` est traitée comme un déplacement, pas comme une écoute. Sans ça, un proche qui tire le curseur jusqu'au bout « écouterait » deux minutes en un geste, et le maillon central de la chaîne H2 mesurerait n'importe quoi. Le reste part aussi à la pause et au `pagehide` : un onglet fermé à la vingt-neuvième seconde ne doit pas perdre la mesure. À revalider : non.

**T-92 — 2026-09-02 — bloc 08 — Le plafond de notification se lit dans les messages **envoyés**, pas dans les réactions.** « Une notification par histoire et par jour » est vérifié sur `outbound_messages`, qui sait ce qui est **parti** — et non sur un compteur d'intentions, qui compterait aussi ce qui a échoué. Trois proches qui réagissent le même soir font donc un message qui les nomme tous les trois. À revalider : non.

**T-93 — 2026-09-02 — bloc 08 — La façade d'analytics existe avant PostHog.** L'interface `Analytics` et l'implémentation `LogAnalytics` arrivent au bloc 08, alors que PostHog n'est prévu qu'au bloc 15. Le motif n'est pas l'anticipation : les événements de la chaîne H2 doivent être émis **pendant** qu'on écrit le code qui les produit, sinon ils sont ajoutés après coup, aux mauvais endroits, et la mesure ne veut plus rien dire. `LogAnalytics` garde en mémoire ce qu'il a capté, ce qui rend éprouvable dès maintenant qu'un événement part au bon moment, une seule fois, et sans donnée personnelle. À revalider : non.

**T-77 — 2026-09-02 — bloc 07 — Un neuvième consentement : la délégation de validation.** Le dossier 04 §2 en nomme huit ; le bloc 07 §6.7 exige un `consent_id` **non nullable** sur `mandates`, ce qui suppose un motif de consentement que le dossier n'avait pas nommé — il ne décrivait pas encore la délégation. `ConsentKind::MandateDelegation` est ajouté, la contrainte `check` de `consents.kind` migrée, et un texte de consentement semé. Le test des énumérations attend désormais neuf valeurs, avec la raison écrite à côté. À revalider : oui, la formulation du texte passe par la relecture juridique du bloc 10.

**T-78 — 2026-09-02 — bloc 07 — Le code de l'espace narrateur est semé, pas exposé par une route.** Le bloc prévoyait « une route de test locale » révélant le code envoyé. Écarté : une route qui expose des codes à usage unique est exactement le genre d'affordance qui finit activée quelque part, et l'exposer même derrière `APP_ENV` déplace le risque sans le supprimer. `E2ELinksSeeder` sème à la place trois narrateurs avec des coordonnées connues et un défi en attente dont le code est connu — le même parti que les liens déterministes du bloc 04. Corollaire produit : la page d'entrée offre « j'ai déjà un code », parce qu'un test qui n'en redemande pas est aussi le parcours de quelqu'un qui a fermé son onglet et retrouve son SMS. À revalider : non.

**T-79 — 2026-09-02 — bloc 07 — La borne par IP des routes à jeton est réglable, et desserrée hors production.** Les deux bornes de `throttle:tokens` ne protègent pas la même chose : celle par **jeton** (20/min) protège du balayage de liens, celle par **IP** (60/min) protège l'infrastructure. La seconde punit le partage de connexion — une maison de retraite, une famille derrière un routeur — et coupait la suite bout en bout, qui concentre trente navigateurs sur une adresse. Elle passe donc en configuration (`THROTTLE_TOKENS_PER_IP`, défaut 60) et vaut dix fois plus hors production. La borne par jeton, elle, est identique partout : c'est elle qui protège réellement les liens, et la relâcher aurait été relâcher la sécurité pour faire passer des tests. À revalider : oui, la valeur de production se réévalue au bloc 16 avec les mesures du pilote.

**T-80 — 2026-09-02 — bloc 07 — L'immuabilité de l'audio source cède devant l'effacement demandé.** Deux principes se rencontraient : « l'audio source est sacré, jamais supprimé **hors état `deleted`** » et le droit du narrateur à faire effacer son récit. Le déclencheur du bloc 04 lisait le premier sans sa réserve : il refusait aussi la mise à `null`, et `PurgeDeletedStory` échouait en base — le droit à l'effacement restait une intention. La règle complète : `original_path` ne peut pas **changer** de valeur, et ne peut être vidé que si l'histoire est `deleted`. L'immuabilité protège contre l'écrasement, pas contre l'effacement consenti. À revalider : non.

**T-81 — 2026-09-02 — bloc 07 — « Garder pour moi » fait redescendre l'histoire à « transcrite ».** Le bloc posait la question sans y répondre. Trois issues étaient possibles ; deux sont mauvaises. Laisser l'histoire en `to_review` la maintiendrait dans la file des relances (règle `recorded_not_validated`, bloc 09) alors que la personne a répondu — on la harcèlerait pour un choix déjà fait. La valider graverait une décision qui doit rester réversible. La transition `KeepStoryPrivate` (`to_review → transcribed`) la sort de la file sans rien graver, et écrit la décision en même temps que l'état pour qu'une chaîne de transcription rejouée ne redemande pas une relecture faite. « Garder pour le livre » reste distinct : coché, il valide et pose `visibility = book_only`. C'est la règle §9 appliquée à la lettre — en cas d'ambiguïté, l'histoire reste privée **et hors livre**. À revalider : oui, c'est un point que le pilote doit observer.

**T-82 — 2026-09-02 — bloc 07 — Une fonctionnalité fermée rend 404, pas 403.** `FeatureClosed` porte un 404. Un « interdit » dirait qu'elle existe et qu'elle est réservée, ce qui invite à insister ; un « introuvable » ne dit rien. Vaut pour le mandat aujourd'hui, et pour tout drapeau fermé ensuite. À revalider : non.

**T-83 — 2026-09-02 — bloc 07 — Un code déjà envoyé ne produit plus une erreur technique.** `OtpService::challenge()` lève `OtpThrottled` au-delà de trois défis par heure, et aucun des trois appelants ne l'attrapait : toucher deux fois « recevoir un code » rendait un 500. Les trois contrôleurs répondent maintenant « un code vous a déjà été envoyé, utilisez celui-là ». Le défaut valait aussi pour la page de code du bloc 03 ; il est corrigé au même endroit. À revalider : non.

**T-84 — 2026-09-02 — bloc 07 — Les tests d'enregistrement tournent en série, avant les autres.** Trois spécifications enregistrent pour de vrai et dépendent du temps réel : `MediaRecorder` doit avoir écrit ses tranches sur le disque du navigateur, et le micro simulé est une ressource partagée. Lancées avec les trente autres, elles échouaient pour une raison qui n'a rien à voir avec le produit. Elles forment un projet Playwright `recorder` à un seul ouvrier, dont le reste dépend — donc en tête, machine au repos. Allonger les délais aurait masqué le problème ; le test de marque avait déjà son projet pour un motif voisin (T-59). À revalider : non.
